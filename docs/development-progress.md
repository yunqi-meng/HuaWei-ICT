并发探测的最终协议计入 HTTP 与连接等待，不为每次请求新建整个 HTTP 客户端。原始“每次初始化客户端”版本主要测得本地初始化开销，报告另存 `artifacts/load-check-client-init.json`；最终报告为 `artifacts/load-check.json`。开发回归报告为 `artifacts/development-evaluation.json`。

后端依赖有 Starlette 的 TestClient/httpx 弃用提示；当前锁定版本的两套测试均通过。前端 npm 提示本机用户配置 `sslVerify`，构建与测试通过。

## 正式使用前仍需外部验收

1. **人工知识审核**：现有 10 条流程、10 篇指南是开发示例，不能把原种子审核字段当作真实维修员签字。真实知识规模扩充至方案目标需要领域人员逐条确认。
2. **独立评测与试点**：方案要求的 120 条独立、人工标注案例、对照实验与真实用户成效尚未取得，不能用本轮 30 条开发回归替代。
3. **可选外部服务**：DeepSeek 已实际验证；SMTP 和 OBS 尚无真实环境验证。未配置时分别明确显示不可发送、使用私有本地附件，不伪造云服务成功。
4. **浏览器验收**：需在可用浏览器中补做布局、键盘、手机输入与现场操作确认。
5. **上线与赛事材料**：按用户要求暂缓云上部署；未虚构 CodeArts 使用记录、真实维修数据、云资源或参赛效果。
