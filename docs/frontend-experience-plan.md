# 前端视觉与交互升级方案

应用技能：frontend-design（视觉设计）、tabbit（实际浏览器验收）。覆盖当前全部路由与账号权限。

## 设计方向

以“精密维修工作台”组织界面：深蓝功能导航、冷白工作区、青蓝操作色，首页用一块可交互的硬件诊断面板建立产品辨识度。科技感来自清晰的数据、设备结构与流程关系，不添加无来源的运行指标、模拟诊断结果或装饰性进度。

基础颜色：导航深蓝 `#0c1425`、工作区冷白 `#f2f5fb`、面板白 `#ffffff`、正文蓝黑 `#17243c`、操作蓝 `#1168ee`、辅助青 `#008da6`。警告、失败、完成各自使用语义色。提供可记忆的深色工作区，使用同一组语义变量；硬件产品图保持可辨识的浅底。

字体以 Bahnschrift 的数字与几何感、Microsoft YaHei UI 的中文正文构成清晰层级，回退到系统中文字体；不依赖外部字体网络。正文约 15–16px，表单至少 16px，主标题 28–36px，数据使用等宽数字。

布局：宽屏采用 232px 常驻侧栏、64px 顶栏和最大 1440px 工作区；窄屏改为可关闭抽屉、单列内容与横向可滚动数据表。正文左对齐，阅读页控制行长，密集数据页保留宽度。

```text
┌──────────┬────────────────────────────────────────┐
│ 知修     │ 当前位置             快速跳转 · 主题 · 账号 │
│ 工作空间  ├────────────────────────────────────────┤
│ 求助/性能 │ 页面标题                         主操作 │
│ 硬件/指南 │                                        │
│ 我的服务  │ 当前任务 / 筛选 / 信息主体               │
│ 管理入口  │                                        │
└──────────┴────────────────────────────────────────┘
```

对照设计要求后的取舍：不采用每页霓虹光晕和重复玻璃卡片；仅首页设备结构承担主要视觉表现，其他页面强调层级与可操作性。去掉无意义的入口编号和大写英文标签，编号只用于真实顺序。动效用于抽屉、选择和反馈，并尊重减少动画偏好。

## 实施范围

### 分区配色微调

保留统一布局、字体和组件尺寸，使用功能分区色丰富界面：故障排查采用青绿，性能对比采用紫罗兰，硬件规格采用靛蓝，做工资料采用玫瑰铜，知识指南采用苔绿，预约与服务采用暖金，设备与账号采用湖蓝，管理概览与系统采用石板蓝。每个分区同时提供浅色与深色变量，仅轻微调整页面底色、选中状态、按钮、焦点与图标；警告、失败和成功的语义颜色保持独立。首页三种服务路径使用各自的青绿、蓝紫和暖金，摘要卡片也使用协调的辅助色，避免整页只有一种强调色。

本轮微调验证：生产构建通过；1440px / 390px、浅色 / 深色共 64 个浏览器场景通过，每个主题实际读取到首页品牌色加 8 组不同分区色，未出现横向溢出；首页三种路径的强调色分别生效。16 套新增浅深配色的主按钮文字对比度最低 4.81。记录位于 `artifacts/section-colors-summary.json`、`section-colors-browser.json` 和 `section-colors-contrast.json`。

- 全局导航：所有功能可发现、权限入口清晰、移动抽屉、键盘快捷跳转、浏览器标题与焦点管理、回到顶部。
- 共享组件：标题、按钮、表单、加载/失败/空状态、弹窗、数据表、来源说明、选择托盘与图表配色。
- 首页/登录：重排内容与主操作，登录密码可显隐，保留原有登录返回路径。
- 求助/排障/预约/服务记录：步骤进度、反馈和主次操作、列表筛选、表单保存状态。
- 硬件/性能/主板/做工/指南：筛选与比较可读性、浅深主题一致性、手机表格与对比面板。
- 维修/运营/排班/编审/系统：密集表单分区、真实统计层级、操作状态与长内容阅读。

## 验收

检查全部页面路由（含详情页面与各权限后台），在隔离测试数据库中验证桌面与手机布局、无横向溢出、导航抽屉/快捷跳转/主题记忆/密码显隐/表单与比较行为；运行现有交互回归和生产构建。浏览器验证不调用付费模型，不改写现有业务库。
