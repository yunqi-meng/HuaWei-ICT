# 项目检查与修复记录（2026-11-05）

本轮在已有未提交改动上检查和修复，保留现有模型优先排障、RAG、天梯数据等功能，以及本地环境配置和业务数据。

## 清理

- 删除前端 6 处未使用的导入或解构变量，启用 TypeScript 的 `noUnusedLocals`、`noUnusedParameters`，纳入现有构建检查。
- 删除后端 4 处未使用的导入；保留明确供外部调用的 `validate_flow_graph` 重导出。
- 删除硬件模块中未被引用的 `_CATALOG`、`CPUS`、`GPUS`，避免导入时多读一次目录文件。
- 删除模型步骤模块中未使用的重复系统提示词，实际提示词仍由 RAG 模块维护。
- 删除不可达的模型分类路径：原调用只发生在模型禁用时，函数本身又会在模型禁用时立即返回。
- 删除依赖文件中已经过时、重复的可选依赖注释。

## 修复

| 问题 | 修复后行为 |
|---|---|
| 非法模型风险等级被降为 `observe`，非法 action 被改为 `continue` | 拒绝该输出并沿用现有降级路径 |
| `options`、`citations` 类型错误可能引起异常或错误解析 | 明确校验列表类型；非文本模型回复直接降级 |
| 安全检查遗漏选项、交接原因，先截断文本可能漏检 | 对这些字段的完整文本执行检查，补充驱动操作及 BIOS/UEFI 匹配 |
| 模型没有可用选项，或唯一选项占用兜底键 | 继续排查时提供至少两个不同键的反馈选项 |

| 模型状态、步骤对象等被列入交接摘要的“已确认事实” | 摘要过滤 `ai_` 内部字段，实际尝试步骤仍单独保留 |
| CPU 每瓦性能始终使用多核成绩 | 根据当前 CPU-Z 指标计算；每瓦图表与表格采用同一数值 |

| 天梯页面混用 Geekbench 来源说明 | 展示天梯文件中的来源和测试口径 |
| API Docker 镜像缺少天梯 JSON 文件 | 将 `ladderCatalog.json` 加入镜像复制清单 |

## 优化

- 天梯页直接从已加载的本地目录计算概况，删除重复的概况 API 请求及其加载状态；后端概况接口保留。
- 单芯片读取只复制命中的条目；芯片对比一次读取目录后按选择顺序提取，避免每个型号都复制整份目录。已验证调用方修改返回对象不会污染缓存。
- BM25 预先计算文档词频和长度，避免在每篇文档、每个查询词的计算中反复扫描整个语料库。800 个模拟分块、4 个查询的对照结果完全一致；三次运行中位耗时约 198.40 ms → 71.00 ms（2.79 倍）。该测量不包含数据库、向量服务或模型耗时。
