# 六分钟演示脚本（对应设计方案 19.2）

## 0:00–0:40 痛点与流程
- 展示首页三入口：描述问题 / 按分类找教程 / 预约人工义诊。
- 说明：用户描述 → 审核流程指导 → 失败转人工带摘要 → 预约到场 → 验收结单。

## 0:40–2:00 低风险问题自助恢复
1. 登录 user@demo.local，选择登记的 Windows 11 故障电脑，输入“Wi-Fi 连上却不能上网”。未选设备时先回答系统确认。
2. 系统匹配已审核流程「Wi-Fi 已连接但网页打不开」，展示当前操作卡：
   “确认是不是只有这台电脑无法上网”（含为什么做、预期现象、来源）。
3. 点“其他设备可以上网” → 进入“检查系统代理设置”（可逆变更标记 + 回退说明）。
4. 点“关闭后网页能打开了” → 进入最终验证；再次打开网页并点“验证后确认已恢复” → 会话 RESOLVED，绿色确认。
5. 强调：来源由服务器绑定，步骤来自发布流程；当前是本地开发示例，不以示例审核字段冒充真实维修人员签字。

## 2:00–3:10 无法线上解决 → 转人工
1. 新会话输入“外接显示器没有画面”。
2. 走两步后选择“还是不行/检测不到显示器” → 进入转人工。
3. 点击“生成交接摘要并提交工单”：展示摘要（设备、已尝试步骤、待确认事项、
   转人工原因），确认提交。
4. 选择义诊活动与时段 → 保留 5 分钟 → 填联系方式确认 → 获得一次性签到码。
5. 可刷新页面继续确认保留；确认后从工单详情点击“更改预约时段”，成功后仅占新时段，失败保留原预约。

## 3:10–4:10 后台派单、签到、维修与验收
1. 换 admin@demo.local：运营概览看到待受理工单 → 派单给志愿者。
2. 换 staff@demo.local：选择已分配工单，看到交接摘要（“用户已做过什么”），
   预约编号自动填入，输入用户出示的签到码核销（错误码被拒），工单进入处理中。维修端不能读取签到码。
3. 填写检查/原因/处理/验证，勾选“作为维修结果提交” → 待验收。
4. 换回用户：核对维修记录，点击“确认上述维修结果并结单” → CLOSED；仅在维修结论为 fixed 时记录为修复。转介等结论照实保留。

## 4:10–4:50 风险场景阻断
1. 新会话输入“笔记本电池鼓包了”。
2. 系统直接进入 HANDOFF：红色安全提醒（不要通电/拆机），不提供任何自助步骤，
   只给转人工入口。
3. （可选）管理员撤回某条流程版本：正在使用该版本的会话下一步被阻断并转人工。
